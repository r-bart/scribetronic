# short-form-x-vs-y

Compare two things to expose a non-obvious preference. The reader should finish thinking _"oh, I hadn't thought of it that way"_.

## Structure (X single, ~280 chars)

```
[X] vs [Y].

[X]: [one-line take, slightly negative or limiting]
[Y]: [one-line take, slightly positive or freeing]

[Closer: the rule you're extracting from the contrast.]
```

## Structure (LinkedIn / longer)

```
[X] vs [Y]. There's no contest.

[2-3 lines on X — what people think, what's actually true.]

[2-3 lines on Y — the alternative.]

[3-5 bullet contrasts:
  X: [trait]    →  Y: [counter-trait]
  X: [trait]    →  Y: [counter-trait]
  ...]

[Closer: the rule.]
```

## Rules

- **Pick comparisons that aren't obvious.** "Cars vs bikes" — boring. "Roadmap vs backlog" or "Sprints vs Kanban" — useful.
- **Both sides must be real.** No straw man. The reader should recognize someone (maybe themselves) on each side.
- **Land the rule.** Don't end on the contrast — end on what the contrast TEACHES.

## Anti-patterns

- "X is the new Y" — overused.
- Comparison without preference. Pick a side.
- More than 5 contrasts in the table. Picks 3.

## Examples to model

Welsh: _"Renting an audience vs owning an audience."_
Welsh: _"Working in public vs working in private."_
