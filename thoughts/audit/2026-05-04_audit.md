## Findings

### MAJOR

**M1. `CLAUDE.md` and `AGENTS.md` describe a stale architecture.**
Both files document a `core/ + infrastructure/ + commands/` layering that does not exist in the codebase. The actual layout is `analyzers/ + generators/ + data/ + commands/`, which matches `docs/ARCHITECTURE.md` (canonical) and `.claude/rules/architecture.md`.

- **Why this matters:** AI agents read `CLAUDE.md` first. They will hallucinate imports against non-existent folders and propose violations against the wrong layer rule.
- **Fix:** rewrite the "Architecture" + "Layer rule" sections of `CLAUDE.md` (lines ~17–60) and `AGENTS.md` (lines ~17–45) to match `docs/ARCHITECTURE.md`. ~30 min.

### MINOR

**M2. Skill count drift (21 vs 22).**
Actual: 22 skills. Cited as "21" in:
- `CLAUDE.md` ("21 skills") and "All 21 skills documented" reference
- `README.md` (3 occurrences: "Install the 21 skills…", "21 skills covering…", table caption)
- `docs/cli-reference.md` (2 occurrences in tree + summary)
- `docs/philosophy.md` ("catalog of all 21 skills")

Only `docs/skills.md` is correct. Recommend search-and-replace `21 skill` → `22 skill`.

**M3. Layer-rule violation in `data/skills.ts`.**
`docs/ARCHITECTURE.md:131` states "`src/data/` holds pure data (no I/O)". The file does `readFileSync`, `existsSync`, and `glob` to enumerate templates and parse SKILL.md frontmatter from disk. Either:
- (preferred) extract the loader to `src/analyzers/skillRegistry.ts` and keep `data/skills.ts` for pure types/constants, or
- relax the rule in `docs/ARCHITECTURE.md` to allow read-only template introspection in `data/`.

Practical impact is small (single file, well-tested) but it's the same kind of doc-vs-code drift as M1.

**M4. Five short-form skill descriptions don't say *when* to invoke.**
Examples (lengths in chars):
- `short-form-x-vs-y` (102): "Welsh format #1" alone won't help the router pick it.
- `short-form-listicle` (106), `short-form-observation` (119), `short-form-present-vs-future` (127), `short-form-carousel-li` (141)

Compare to `style-extract` (362) which clearly states what + when ("Usar cuando el usuario quiera crear o refrescar la guía de estilo…"). Beefing these up improves auto-invocation reliability.

**M5. `package.json` repo URL needs verification before tagging `v0.1.2`.**
Points to `github.com/r-bart/scribetronic.git`. Matches `git remote -v`. Confirm the GitHub org/repo exists, that `NPM_TOKEN` is set in repo secrets (release workflow uses it), and that the npm package name `scribetronic` is owned by your account before the first tag.
